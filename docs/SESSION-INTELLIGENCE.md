# B03 Session Intelligence
Policy v1: conventional analytical windows, Tokyo 09:00, London 08:00, New York 08:00 local, each 9 hours, weekdays. IANA timezone rules handle DST separately. This changes the prior fixed Dhaka schedule; user-specific trading preparation/execution schedules are separate future settings. OTC FX has no single official venue clock; this is a product convention, not broker hours.
Weekly FX window: Sunday 17:00 to Friday 17:00 America/New_York. Holidays, broker exceptions and asset-specific calendars not yet supported. Weekend session selection retains latest weekday start and labels inactive. Read-only authenticated GET /api/analysis/sessions returns success/data, ISO asOf, fxWeekOpen, selected, active array, overlap boolean, and session windows with Unix seconds start/end/OR end/next start, local session date, timezone and Dhaka startHour. No credit charge.
Radar uses the same session resolver for auto, explicit and daily publishing. Opening range requires exactly four consecutive closed 15m candles. Optional orBreach (UP/DOWN/null), orBreachTs (close timestamp seconds/null) identify a fresh last-closed-bar crossing, not sustained state. No event outside active session, on stale/gapped candles or in-progress OR. Existing orConfirmed is a directional state; inactive sessions use trend-only scoring and warning. No new FX focus/watch outside standard weekly market window. Closed market status independent of stale feed.
Tests committed for DST mismatch, winter/summer, overlap, weekend, boundaries, OR and crossing. Full build and integration tests, migration, provider licensing, data coverage, historical event persistence and session-specific backtests remain required. No frontend changes.
